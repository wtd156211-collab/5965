# 分层配置合并库

我们服务有七八个配置来源：默认值、环境文件、远端覆盖、环境变量、命令行。现在合并逻辑散在各处，谁改谁踩，经常出现明明在命令行给了值却不生效的情况。想自己写一个配置合并的库。

规则写死在下面：各层的优先级、同名字段怎么覆盖、数组是按索引覆盖还是整体替换、空值算不算一次覆盖、嵌套字段的优先级怎么叠。另外字段名支持嵌套路径写法，路径写错要在**加载的时候**就报出来，别等到取值才发现；配置里可以引用别的配置项，引用要能解析，循环引用必须挡住并说清楚是哪个环。合并结果要确定：同一组输入跑两遍结果一模一样，嵌套对象的键顺序也不能飘。性能上，上千个键、七八层的配置合并要在几十毫秒内完成，别每次都把整棵树重新深拷贝好几遍。实现只用标准库，测试用 unittest。

仓库里只有这份说明和 samples 里的分层配置，代码从零写。

## 分层与优先级

五层，按下面的顺序从低到高合并，后面的覆盖前面的：

| 顺序 | 层 | 文件 | 说明 |
| --- | --- | --- | --- |
| 1（最低） | 默认值 | `defaults.json` | 必填，**它同时定义了合法路径的集合** |
| 2 | 环境文件 | `file.json` | 随环境走的配置文件 |
| 3 | 远端覆盖 | `remote.json` | 配置中心下发的覆盖 |
| 4 | 环境变量 | `env.json` | 「路径 → 值」的扁平映射 |
| 5（最高） | 命令行 | `cli.json` | 「路径 → 值」的扁平映射 |

`env` 与 `cli` 两层因为来源于字符串，规定写成扁平映射（键是路径），值按 JSON 解析（`"123"` 当数字、`"true"` 当布尔、`"null"` 当空值），解析不了的当字符串处理。

## 合并规则

1. **同名字段**：高优先级层直接覆盖低优先级层的值；
2. **嵌套对象深合并**：两层的同名键都是对象时，逐个子键递归合并，**每个叶子键各自按优先级取最高层的值**（不是整棵子树替换）；
3. **数组整体替换**：任何一层给出数组，就把低优先级层的整个数组换掉，**不按索引合并**；
4. **`null` 算一次覆盖**：显式写 `null` 会把该键的值置为 `null`；键**缺失**不算覆盖，低优先级的值保留；
5. **类型不同整体覆盖**：高优先级是标量、低优先级是对象（或反过来）时直接换掉，不做任何兼容尝试。

## 路径写法与校验

路径用点号分段，数组元素用方括号下标：`server.port`、`pools[1].size`、`matrix[0][1]`。

- 路径里出现的每一段都必须能在**默认值树**里走通；走不通就在加载阶段报 `UNKNOWN_PATH`（带路径），不许等到运行时查值才报；
- 路径语法本身不合法（空段、下标不是数字、方括号没闭合）报 `BAD_PATH`。

## 引用语法

- **整串**形如 `${路径}` 的字符串才算引用（路径可以用上面那套写法和数组下标）；
- 引用在**最终合并结果**上解析：先按优先级合并出完整配置，再把引用替换成目标当前位置的值，所以「远端覆盖过的值」也会被引用看到；
- 支持链式引用（引用的目标本身又是引用），按依赖顺序解析；
- **循环引用**报 `CYCLE`，detail 里给出环上的路径，用 `->` 连接，起点取环里路径最小（UTF-8 字节序）的那个；
- 引用目标不存在报 `UNKNOWN_REF`；字符串以 `${` 开头但不是完整的 `${路径}`（例如 `${a}/b`，容易让人误以为会做字符串插值）报 `BAD_REF`；`${` 出现在字符串中间时按普通字符串处理，不当引用。

## 输出格式

合并成功时输出合并结果的 JSON：缩进 2 空格，行尾 LF，**键顺序固定为默认值树里的顺序**（递归保持），所以同一组输入两次输出逐字节一样。

失败时只输出一行：

```text
error,<错误码>,<detail>
```

detail 里不含逗号（用 `=`、`->` 这些符号分隔），便于逐字段对拍。

## 错误码

| 错误码 | 什么时候报 | detail 形式 |
| --- | --- | --- |
| `BAD_PATH` | 路径语法不合法 | `path=<原样路径>` |
| `UNKNOWN_PATH` | 路径在默认值树里走不通 | `path=<原样路径>` |
| `BAD_REF` | 以 `${` 开头但不是完整引用 | `value=<原样字符串>` |
| `UNKNOWN_REF` | 引用目标不存在 | `ref=<被引用的路径>` |
| `CYCLE` | 引用成环 | `<p1>-><p2>->…-><p1>` |

检查顺序：先解析并校验 `env`、`cli` 两层的路径（出错立刻返回），再合并五层，最后解析引用。

## 性能与确定性

- 上千个键、七八层嵌套的配置，合并要在**几十毫秒**内完成；实现上按需遍历，别对每一层都做一次整树深拷贝（`samples/case-6` 就是给这条用的：20 组 × 50 键 × 7 层，五层覆盖）；
- 输出键顺序、环的起点、错误返回顺序都由规则写死，同一组输入跑两遍结果必须逐字节一样。

## 样例

```text
samples/case-N/{defaults,file,remote,env,cli}.json   五层输入
samples/case-N/expected.txt                          期望结果（合并后的 JSON 或 error 行）
```

| 用例 | 内容 | 期望 |
| --- | --- | --- |
| case-1 | 常规合并：对象深合并、数组整体替换、`null` 覆盖、缺失键不动 | JSON |
| case-2 | 路径写法：`pools[1].size`、`matrix[0][1]`、整体替换 `meta.tags` | JSON |
| case-3 | 引用：链式引用、引用数组元素、被引用值被远端覆盖后的结果 | JSON |
| case-4 | 循环引用 `a → b → c → a` | `error,CYCLE,b->c->a->b` |
| case-5 | 路径写错（`server.hots`） | `error,UNKNOWN_PATH,path=server.hots` |
| case-6 | 大配置：20 组 × 50 键 × 7 层，五层覆盖 | JSON（约 260 KB） |

## 用法

```bash
# 合并一个用例目录，成功输出 JSON（退出码 0），失败输出 error 行（退出码 1）
python -m configmerge samples/case-1

# 跑全部测试（含六个样例的逐字节对拍与性能断言）
python -m unittest discover -s tests
```

库入口：

```python
from configmerge import merge_config, render, ConfigError

layers = {"defaults": {...}, "file": {...}, "remote": {...},
          "env": {"server.port": "7070"}, "cli": {...}}
try:
    tree = merge_config(layers)   # 合并 + 引用解析
    text = render(tree)           # 固定格式 JSON
except ConfigError as err:
    print(err.line())             # error,<错误码>,<detail>
```

## 实现说明

### 按需遍历，不深拷贝

- `defaults` 只展平一次：递归得到「路径元组 → 叶子值」映射（`merge.py` 的
  `_flatten_defaults`）。对象和数组都向下递归（数组元素用 `pools[1].size`
  这类下标路径定位），只有标量（含 `null`）是叶子。
- 其余四层各自遍历自身：**只有「层值与默认值同位置都是对象」时才下钻**，
  否则整个值直接作为该路径的叶子覆盖。因此数组整体替换、类型不同整体覆盖
  都是一次赋值；覆盖时写入的是值的引用，不复制，整次合并没有任何深拷贝。
- 输出树只构建一遍：按 `defaults` 的原始键序与数组顺序递归；某条路径被高层
  整体给过值就原样引用，否则逐元素取叶子。键顺序因此被默认值树钉死。

### 引用解析顺序与环检测

- 先合并完五层，再遍历最终结果树找整串 `${路径}`（`refs.py`）。所以引用
  看到的永远是覆盖后的当前值，远端覆盖可见。
- DFS 解析：解析路径 P 时先看目标当前值；若目标本身也是引用就沿依赖边继续，
  天然按依赖顺序完成链式解析；已解析路径做记忆化，每条路径只解析一次。
- 环检测用「活跃路径集合 + DFS 栈」：再次踩到栈上路径即成环，detail 取栈中
  该路径之后的环段（路径以规范形式 `pools[1].size` 表示），环段旋转成
  「最小路径的后继开头、最小路径收尾」，保证从哪个节点进入 DFS 结果都一致，
  即 `b->c->a->b` 这种形式。
- `${` 出现在字符串中间按普通字符串处理；以 `${` 开头但不是完整 `${...}`
  （如 `${a}/b`）在遍历到该叶子时立刻报 `BAD_REF`。

### 路径索引缓存

- 路径语法解析结果（路径文本 → 段元组）在单次合并内用一个 dict 缓存
  （`resolve(..., cache=...)`）。case-6 里 env/cli 校验与五层合并会重复
  命中同一长路径文本，解析只做一次；默认值树本身是有序结构，遍历即索引，
  不需要另建索引结构。
- 缓存只在单次 `merge_config` 内有效，不做跨调用缓存，避免多份默认值树
  之间串数据。

### 确定性

- 每层内部按键的 UTF-8 字节序（Python 默认字符串序）遍历，报错顺序固定；
  env、cli 先校验（env 先 cli 后），再合并五层，最后解析引用——与上面的
  检查顺序一致。
- 输出为 `json.dumps(result, indent=2)` + 单个 LF，同一组输入两次输出
  逐字节相同；样例 case-6（20 组 × 50 键 × 7 层、五层覆盖）端到端约 7ms。
